# VulkanInteropApi contract

Owner: R2. Status: v1, from the R2 merge; later changes go through a `contract-change` PR with a CHANGELOG entry and updated vectors. Consumers: the Vulkan backend (V1), `lrm devices-vulkan`, `apps/VkDeviceCheck`, and tests that drive Vulkan. Code: `src/Lrm.Gpu.Vulkan.Interop` (namespace `Lrm.Gpu.Vulkan.Interop`), generated by `tools/vkgen` and checked by `tools/abi-oracle/vulkan`. Tests: `tests/Lrm.Gpu.Vulkan.Interop.Tests` (cpu, gpu and bench tiers). Rationale and evidence: ADR [R2-0001](../decisions/R2-0001-vkgen-and-vulkan-interop.md).

How LRM talks to Vulkan from F#: every type, value and command signature comes from the Khronos registry (vk.xml) through a generator, `bindings.json` is the single list of what is bound, and an independent oracle compiles the runtime layout against the Vulkan headers with cl.exe.

## Rules

1. **vk.xml names, ABI order.** Generated structs, unions, members, enums, enum members, handles, commands and parameters carry their vk.xml names (F# keywords such as `type` and `module` are escaped with double backticks). Struct members are in declaration order, which is the C ABI order.
2. **One list.** `tools/vkgen/bindings.json` is the only list of bound items, for the generator and for the oracle. What it does not reach is not bound. Hand-written code never declares a Vulkan struct, enum or command.
3. **Blittable only.** The assembly carries `DisableRuntimeMarshalling`. Every struct is blittable, with equal managed and marshalled sizes. Every pointer in a struct member or a delegate is `nativeint`; there is no `string`, `bool` or class in any signature.
4. **Generated dispatch tables.** Commands are called through three generated tables, each loaded once: `VkGlobalCommands` (through `vkGetInstanceProcAddr(NULL, …)`), `VkInstanceCommands` (through `vkGetInstanceProcAddr(instance, …)`) and `VkDeviceCommands` (through `vkGetDeviceProcAddr`). A call never looks a command up, and a wrapper call allocates nothing.
5. **pNext chains live in one stack frame.** Every struct of a chain is a local of the frame that makes the call. The recipe's chains are byref-like structs (`FeatureChain`, `PropertiesChain`), so the compiler keeps them there. Pointers are pinned only for the call that uses them.
6. **Callbacks stay rooted.** A delegate whose function pointer is handed to Vulkan (`DebugMessenger`) is held by a GCHandle from before the Vulkan object is created until after it is destroyed, whether or not its owner is still reachable, and the callback never throws into the driver. The instance destroys such objects that are still alive (owners that never disposed them) before `vkDestroyInstance`.
7. **Every enum match has a wildcard arm.** Vulkan enums are open: drivers return values this binding does not name. FS0104 is an error under TreatWarningsAsErrors, and no R2 source silences it.
8. **No tail calls around stack addresses** (as D3D12ComIdiom rule 3). Wrappers take `const T*` as `inref` and `T*` as `byref`, so F# never compiles a call to them as a tail call. Span and `nativeint` arguments do not have that property, and neither do raw delegate calls: every project that calls the interop builds with `Tailcalls=false` (`Directory.Build.props`, ProjectGraph), and the cpu tier scans the interop and its tests for `tail.`.

## Generated API

`tools/vkgen` writes three files, never edited by hand:

| File | Contents |
| --- | --- |
| `Vk.g.fs` | `VkConst` (API constants, `VK_HEADER_VERSION`, each bound extension's name and spec version); basetypes; handles; enums and FlagBits; bitmask typedefs; enum aliases; inline arrays and structs and unions in dependency order; struct aliases; funcpointer delegates; one `PFN_<command>` delegate per command |
| `VkCommands.g.fs` | `VkGlobalCommands`, `VkInstanceCommands`, `VkDeviceCommands`: per command its raw delegate (member `vkX`, null when not loaded) and its wrapper (member `X`, the name without `vk`); `Names`, the bound commands in `bindings.json` order; `Missing`, the commands whose entry point was NULL |
| `VkMeta.g.fs` | `VkMeta`: the header version, the core version, the bound extensions, every struct's sType, structextends, flags and the generator's own C layout (size, alignment, members with offsets and sizes), every command's level, providers and success codes, and the type aliases |

**Types:**

| vk.xml | F# |
| --- | --- |
| Basetype (`VkBool32`, `VkFlags`, `VkFlags64`, `VkDeviceSize`, `VkDeviceAddress`) | An abbreviation of its scalar (`type VkDeviceSize = uint64`) |
| Enum | An F# enum over `int32`, members named and valued as in C |
| FlagBits | A `[<Flags>]` enum over `uint32`; over `uint64` for a 64-bit (`bitwidth="64"`) FlagBits |
| Bitmask typedef (`VkBufferUsageFlags2`) | An abbreviation of its FlagBits enum when that has members, else of `VkFlags` or `VkFlags64` |
| Dispatchable handle (`VK_DEFINE_HANDLE`) | A struct over one `nativeint` with `Null`, `IsNull` and value equality |
| Non-dispatchable handle | A struct over one `uint64`, the same members |
| Struct | `LayoutKind.Sequential`, `val mutable` members; with an sType member also `StructureType` and `Create()` (zeroed, sType set) |
| Union | `LayoutKind.Explicit`, every member at offset 0, `Size` the largest member rounded up to the union's alignment |
| `T name[N]` | An `[<InlineArray(N)>]` struct `Array<N>_<element>` with `ToArray()`; `char[256]` also has `AsString` |
| Pointer member or `PFN_*` member | `nativeint`, documented with its C declaration |
| Funcpointer | An unmanaged delegate (`CallingConvention.Winapi`) |
| Type alias (`VkDeviceAddressRangeEXT`) | An abbreviation of its target |

**What is bound.** Core versions up to `coreVersion` (1.4) and the extensions listed (`VK_EXT_descriptor_heap`, `VK_KHR_shader_untyped_pointers`, `VK_EXT_memory_budget`, `VK_EXT_debug_utils`, `VK_EXT_device_fault`, `VK_KHR_cooperative_matrix`, `VK_KHR_calibrated_timestamps`) decide which enum values, sType values and extension constants exist and which providers a command has (vk.xml `<require>` blocks, with `depends` expressions evaluated against that set). An enum gets the members of its `<enums>` block and those additions. Roots are the listed structs, enums, funcpointers and commands; the closure adds what they reach by value and the structs and handles that command parameters point to. Today: 109 structs and unions, 10 inline arrays, 53 enums, 16 handles, 1 funcpointer and 96 commands (5 global, 20 instance, 71 device).

**Wrappers.** A wrapper's parameters follow the C parameters:

| C parameter | Wrapper |
| --- | --- |
| By value | The F# type |
| `const T* p`, one element (no `len`), not optional, T bound | `inref<T>`, pinned for the call |
| `T* p`, one element, the pointer not optional | `byref<T>`, pinned for the call (`VkBuffer* pBuffer`, `uint32_t* pCount`) |
| `void** pp` (no `len`) | `byref<nativeint>` (`vkMapMemory`) |
| `const T* p` with `len` a by-value count | `ReadOnlySpan<T>`; the count is dropped and passed as the span's length; `void*` data becomes `ReadOnlySpan<byte>` |
| `T* p` with `len` a by-value count | `Span<T>` |
| Two arrays with one count | Two spans; unequal lengths raise `ArgumentException` before the call |
| `const VkAllocationCallbacks* pAllocator` | Dropped; NULL is passed |
| Anything else (optional pointers, strings, counts behind a pointer, `len` expressions) | `nativeint`, as in C |

An empty span passes NULL. A command that returns VkResult raises `VulkanException(command, result)` unless the result is one of its vk.xml `successcodes`; with VK_SUCCESS as the only success code the wrapper returns `unit`, otherwise it returns the result (`vkWaitSemaphores` gives VK_SUCCESS or VK_TIMEOUT). A success code named by an unbound alias maps to the bound member with the same value (`VK_PIPELINE_COMPILE_REQUIRED_EXT` is `VK_PIPELINE_COMPILE_REQUIRED`). A NULL entry point raises `VulkanMissingCommandException` at the call.

## Instances, devices and chains

- **Loader.** `VulkanLoader.TryOpen()` opens `vulkan-1.dll` (or `libvulkan.so.1`) with `NativeLibrary` and binds only `vkGetInstanceProcAddr` by symbol. `CreateInstance(InstanceOptions)` creates a Vulkan 1.4 instance; `InstanceOptions.create name debugUtils` adds `VK_EXT_debug_utils`.
- **Instance.** Its table, `LiveObjects` (the instance-level objects created on it and not yet destroyed), the physical devices, device extensions, properties, queue families, memory properties, the memory budget (`VK_EXT_memory_budget`, which a physical-device query needs supported, not enabled), cooperative-matrix shapes, calibrateable time domains, tool properties and `vkGetPhysicalDeviceDescriptorSizeEXT`.
- **FeatureChain**, the chain of VulkanHeapRecipe section 1: `VkPhysicalDeviceFeatures2` (shaderStorageBufferArrayDynamicIndexing) → `Vulkan12Features` (bufferDeviceAddress, timelineSemaphore, runtimeDescriptorArray) → `Vulkan13Features` (synchronization2) → `Maintenance5Features` (maintenance5) → `DescriptorHeapFeaturesEXT` (descriptorHeap), optionally → `FaultFeaturesEXT`; `VkPhysicalDeviceVulkan14Features` is never linked. `FeatureChain.link` links the parts a device's version and extensions make valid (`forQuery`) or the creation parts (`forCreate`); `enableRecipe` sets exactly the recipe's bits. The device check queries over the same chain that `Device.create` enables.
- **PropertiesChain:** `VkPhysicalDeviceProperties2` → `Vulkan11Properties` → `Vulkan12Properties` → `Vulkan13Properties` → `Vulkan14Properties` → `DescriptorHeapPropertiesEXT` → `CooperativeMatrixPropertiesKHR`, each only when valid. The per-version structs stand in for the promoted ones (driver, ID, float controls), which are never linked beside them.
- **VkChain.** `prepend` links a struct of the caller's frame. `walk` reads a chain's sTypes (at most 64 nodes). `problems parent first` checks the chain that starts at `first` (the parent's pNext) against vk.xml: every node a bound struct that may extend `parent`, no struct twice unless it allows duplicates, and an end.
- **Device.create instance physical options** creates the recipe's device: Vulkan 1.4, `VK_EXT_descriptor_heap` and the five features, one queue of the recipe's family (the first with COMPUTE, without GRAPHICS and with `timestampValidBits` > 0), `pEnabledFeatures` NULL. It checks the chain with `VkChain.problems` first and raises `InvalidOperationException` for a device without the extension or the family. `DeviceOptions.recipe` is exactly the recipe; `DeviceOptions.diagnostics` adds `VK_EXT_device_fault` with `deviceFault` and `VK_EXT_memory_budget` where supported; `Extensions` adds feature-less extensions (each must be supported). Device commands of instance extensions fall back to `vkGetInstanceProcAddr`. `Device.MissingEnabledCommands` lists the bound device commands whose provider is enabled but whose entry point is NULL. Disposing waits for the device to go idle and destroys it.
- **Diagnostics.** `DebugMessenger` (severities, sink) emits each message as a `gpu.debug.message` event; disposing it, or else disposing its instance, destroys it and frees the callback's root (`IsDisposed`). `DebugUtils` names objects and opens and closes command-buffer and queue labels. `DeviceFault.query` returns `NotEnabled`, `NoFault result` (a driver that has nothing to describe; NVIDIA 616.92 answers a device that is not lost with VK_ERROR_UNKNOWN) or `Fault report`, which is also a `gpu.device.fault` event.

## Device check

`DeviceCheck.check instance physical` observes one device and judges it; `checkAll loader` creates an instance and checks every device inside a `gpu.device.discover` span. Each verdict is a `gpu.device.check` record (`backend`, `device`, `vendor_id`, `device_id`, `driver`, `api`, `max_push_data_size`, `reason`), and every memory heap's size, budget and usage a `gpu.device.memory` gauge (`pool`, `device_local`, `kind`).

A device is **accepted** when all of these hold, and **rejected** with the reasons otherwise:

| Rule | Why |
| --- | --- |
| Device API version ≥ 1.4 | VulkanHeapRecipe section 1 |
| `VK_EXT_descriptor_heap` supported and `descriptorHeap` | The binding path |
| `maxPushDataSize` ≥ 256 (`RequiredPushDataSize`) | The acceptance floor: the D3D12 root-signature limit, so both backends accept the same argument budget (ADR R2-0001). The recipe itself pushes 128 bytes (`RecipePushDataSize`) |
| `vkGetPhysicalDeviceDescriptorSizeEXT(STORAGE_BUFFER)` = `bufferDescriptorSize` | Recipe section 1 |
| The 64-slot heap (section 3) fits `maxResourceHeapSize` | Recipe section 1 |
| `bufferDescriptorSize` > 0, `bufferDescriptorAlignment` and `imageDescriptorAlignment` powers of two, `bufferDescriptorSize` a multiple of `bufferDescriptorAlignment` | `Heap.vulkanGeometry` (Lrm.Gpu.Core), with which V1 sizes the heap, refuses other limits; `DeviceCheck.heapReasons` holds these heap rules and agrees with it |
| `VK_KHR_shader_untyped_pointers` supported | Recipe section 1 (see Open points) |
| `shaderStorageBufferArrayDynamicIndexing`, `bufferDeviceAddress`, `timelineSemaphore`, `runtimeDescriptorArray`, `synchronization2`, `maintenance5` | Recipe section 1 |
| `maxStorageBufferRange` ≥ 2^30 | A 1 GiB page is one storage-buffer descriptor |
| A queue family with COMPUTE, without GRAPHICS, with timestamps | Recipe section 1 |

Reported, never required: descriptor-heap capture replay, untyped pointers, cooperative matrix (and its shapes), device fault, memory budget, calibrated timestamps, `shaderDenormPreserveFloat32` and `shaderDenormFlushToZeroFloat32`, float16 and int8, the memory types and heaps. The driver version is written as its vendor writes it (NVIDIA 10.8.8.6 bits: 616.92; Intel on Windows 18.14 bits; otherwise VK_MAKE_API_VERSION).

`lrm devices-vulkan [--json]` and `VkDeviceCheck [--json]` first compare every struct's runtime layout with VkMeta (`LayoutCheck.run`), then print the report. `lrm devices-vulkan` exits 0 when a device is accepted, 1 without a loader, 2 on a usage error, 3 when none is accepted and 4 on a layout mismatch; VkDeviceCheck exits 0, 1, 2 (layout mismatch) and 3.

## Generation

- **The pin.** vk.xml 1.4.365 is the `vkxml` entry of `tools/bootstrap/toolchain.json` (size 3,341,644, SHA-256 `4ab953836756807a93cee72bc3c63554826b445af43003e0d7d7e876818428ca`), installed by `pwsh tools/bootstrap/bootstrap.ps1` under `LRM_DATA`. The generator checks size and SHA-256 before reading, and reads it as data.
- **Commands.** Regenerate: `dotnet run --project tools/vkgen/Lrm.Tools.VkGen -c Release`. Codegen diff: `pwsh tools/vkgen/check.ps1` (`-NoBuild` in CI); 0 current, 1 stale, 2 error, 4 vk.xml missing or different. After a bindings change, refresh the oracle with `pwsh tools/abi-oracle/vulkan/run.ps1 -Update` in the same commit.
- **Determinism.** The output is a pure function of `bindings.json` and vk.xml, sorted by name and in dependency order, with LF endings; two runs give the same bytes.
- **Stops.** The generator stops on: a listed item that is not in vk.xml or not of its kind, a command alias instead of its target, a command at another level than its list, a command no bound version or extension provides, a struct whose sType is not bound, a bit field, a multi-dimensional array, an array parameter, or a type it cannot bind.

## ABI oracle

`tools/abi-oracle/vulkan` checks the runtime, not the generator. `Lrm.Gpu.Vulkan.Interop.Tests abi-oracle` loads the interop and dumps what the CLR uses:

| Fact | Runtime source | Checked as |
| --- | --- | --- |
| Struct and union size | `RuntimeHelpers.SizeOf`, equal to `Marshal.SizeOf` | `sizeof(T) == n` (C11) |
| Alignment | The offset of the type after one byte in a two-field struct | `_Alignof(T) == n` |
| Member offset | `Marshal.OffsetOf` | `offsetof(T, f) == n` |
| Member size | `RuntimeHelpers.SizeOf` of the member's type | `sizeof(((T *)0)->f) == n` |
| Member kind | pointer, handle, integer or enum, float, struct, array | Against `decltype` of the C member (C++17); arrays also by rank, extent and element kind |
| Enum and 32-bit flag values | The F# literals | `(long long)E == v`; FlagBits compared unsigned |
| 64-bit flag values | The F# literals | In C++ (vulkan_core.h makes them `static const`) |
| Handle size | `RuntimeHelpers.SizeOf` | `sizeof(H) == 8` |
| Constants | `VkConst` literals | Integers in C; strings (`std::string_view`) and floats in C++; `VK_HEADER_VERSION == 365` |
| Signatures | Every command and funcpointer delegate's `Invoke` | Return and every parameter (kind and size) and the arity, against the `PFN_*` typedef |
| Exact types | Each field's, return value's and parameter's .NET type, named by its `VkStruct`, `VkUnion`, `VkEnum` or `VkHandle` attribute, or a scalar's width and sign | `std::is_same` with the C type of the member or `PFN_*` parameter (C++17): a handle is that handle, a struct or union that one, an enum that enum (a FlagBits enum or its Flags typedef), `uint32` is `uint32_t`, a byte `uint8_t` or `char`; a `nativeint` is a pointer and no handle; array elements likewise |
| Handles | Every `VkHandle` type | A handle in C: a pointer to a struct no header defines (`VK_DEFINE_HANDLE`, `VK_DEFINE_NON_DISPATCHABLE_HANDLE`), not a mere pointer |
| Wrapper pointers | Each wrapper's `inref<T>`, `byref<T>`, `ReadOnlySpan<T>` and `Span<T>` parameter, matched by name to the raw delegate's parameter | That C parameter is a pointer to exactly T (a byte span also to `void`), `const` exactly for `inref` and `ReadOnlySpan` |
| Parameter names | Every delegate's `Invoke` parameter names | Equal, in order, to its `PFN_*` typedef in `vulkan_core.h` (read as text), so the by-name match of wrapper parameters is the header's order |
| sType | Each struct's `StructureType` | `vk::T::structureType` and `vk::T::NativeType` (vulkan.hpp) |
| structextends | `VkMeta.Structs` | `vk::StructExtends<Child, Parent>` for every bound parent |
| Aliases | `VkMeta.Aliases` | `std::is_same_v<Alias, Target>` |

- **Running it.** `pwsh tools/abi-oracle/vulkan/run.ps1` fails when the committed `vk_abi.g.c` and `vk_sig.g.cpp` differ from the dump (`-Update` rewrites them), compiles them with cl.exe from VS 2022 Build Tools (vswhere, `vcvars64.bat`) with `/W4 /WX` and the headers as external headers, links `oracle_main.c` and runs it. The headers are the `vkheaders` entry of `toolchain.json`; their `vulkan_core.h` is checked against the install record bootstrap wrote. - **Today's result.** 5,776 compile-time checks (2,801 C, 2,975 C++) against Vulkan-Headers 1.4.365, 0 failures; the parameter names of all 97 delegates match `vulkan_core.h`.

## Verification

The cpu tier (CI) checks:
- that vkgen regenerates the committed files byte for byte and that two runs into a fresh tree give the committed bytes with LF endings; a missing vk.xml is a skip recorded as `gpu.codegen.vulkan.skipped`, never a pass;
- that `VkMeta` and the three tables hold exactly `bindings.json`'s lists;
- every struct's runtime layout against VkMeta, the layout, KAT-1 and KAT-2 vectors, the registry values and the handle shapes; that `DeviceCheck.heapReasons` and `DeviceCheck.geometry` agree with `Heap.vulkanGeometry` on KAT-2 and 14,400 more limit sets (the same devices refused, the same geometry);
- the ABI oracle with 0 failures, its committed sources current, one exact-type check per field, parameter, return value and wrapper pointer parameter, the delegates' parameter names against `vulkan_core.h`, its 27 mutants, and the spike cross-check;
- the wrappers on fake entry points: inref pinning (the callee sees the caller's struct), span lengths as counts, NULL for an empty span, unequal spans raising, byref outputs, NULL `pAllocator`, raising and success codes, the missing-command exception, zero allocation, and that every command delegate is unmanaged and blittable;
- the chains: recipe order, exactly the recipe's feature bits, the fault struct only when asked, `VkChain.problems` on a wrong parent, a duplicate and a cycle, unique sTypes and `Create()`;
- the device-check rules: the RTX 4080's capabilities are accepted, each missing requirement (the heap rules included) gives exactly its reason, the push-data floor and the 1 GiB bound, driver versions and the queue family;
- tail calls (no `tail.` in the interop or its tests; a consumer compiled with `--tailcalls+` has none at inref or byref wrappers, while its raw-delegate control has one), FS0104 never silenced, and the chain structs byref-like.

The gpu tier (vulkan mutex) checks that the RTX 4080 is accepted; that the recipe's device is created with the full feature chain and destroyed cleanly twice, with every enabled device command and every enabled instance command loaded; that recording 3,000 wrapper calls into a real command buffer allocates no managed memory; that hello-compute is bit-identical twice and equals KAT-4 with no poison left, and its negative control fails; and that debug utils, the diagnostics device (device fault and memory budget), cooperative-matrix properties and calibrated timestamps work; a messenger dropped without Dispose still receives a submitted message after three full collections, and disposing its instance destroys it. Its run log (kind `kernels`) carries the `gpu.dispatch` interval of `args_echo` and the device records.

The bench tier measures the cost of a wrapper call into the driver (`gpu.interop.call`): 60 to 80 ns for `vkCmdPushDataEXT` and 150 to 170 ns for `vkCmdPipelineBarrier2` on the RTX 4080 across runs, driver work included.

## Open points

- VulkanHeapRecipe section 1 calls `VK_KHR_shader_untyped_pointers` an extension dependency of `VK_EXT_descriptor_heap`; vk.xml 1.4.365 does not list it. The device check follows the recipe until R1 changes it.
- Enabling `VK_EXT_device_fault` (`DeviceOptions.diagnostics`) goes beyond the recipe's one extension; V1 and R1 decide whether the recipe allows it.
