# ADR R2-0001: The Vulkan interop is generated from vk.xml and checked by an independent oracle

- **Status:** accepted (R2, 2026-10-18).
- **Owner:** R2.
- **Scope:** `tools/vkgen`, `src/Lrm.Gpu.Vulkan.Interop`, `tools/abi-oracle/vulkan`, the shared Vulkan device check, and the VulkanInteropApi contract ([`docs/contracts/vulkan-interop.md`](../contracts/vulkan-interop.md)), which is the normative text.

## Context

V1 builds the Vulkan backend on this interop, in F#, with our own P/Invoke bindings and no Silk.NET, TerraFX or Vortice (fixed decisions in `CLAUDE.md`). Before this workstream the interop was query-only: a few hand-written structs, transcribed layouts and a Python layout script. R1's spike (`spikes/vk-heap`) proved the descriptor-heap path with a second set of hand-written structs. V1 needs the full hello-compute surface (VulkanHeapRecipe sections 1 to 6) plus diagnostics, and every struct, enum value and signature must be right the first time: a wrong offset on the GPU fails silently or intermittently. AP-1 approved vk.xml and Vulkan-Headers 1.4.365 on 2026-10-18, so both can be used as data.

## Decision

1. **One source, one list.** `tools/vkgen` reads the pinned vk.xml (its SHA-256 is checked against the `vkxml` entry of `tools/bootstrap/toolchain.json` before reading) and `tools/vkgen/bindings.json`, the single list of bound items. Roots are structs, enums, funcpointers and commands; the generator adds what they reach by value and the structs that command pointer parameters point to. Pointer members pull nothing in.
2. **Enum values from the bound API only.** An enum gets the members of its `<enums>` block and the values that core 1.0 to 1.4 and the seven bound extensions add (depends expressions evaluated against that set). F# enums are open, so an unbound value still round-trips; FS0104 is an error under TreatWarningsAsErrors, so every match on a Vulkan enum has a wildcard arm. Member names are the C names.
3. **Types.** Basetypes and bitmask typedefs are F# abbreviations; a bitmask typedef abbreviates its FlagBits enum when that has members, so flags are typed. VkFlags64 bitmasks are uint64 enums. Handles are 8-byte structs over `nativeint` (dispatchable) or `uint64` (non-dispatchable). Unions are `LayoutKind.Explicit` with every member at offset 0 and `Size` set to the largest member rounded to the union's alignment. Fixed arrays are `[<InlineArray(n)>]` structs. Pointer members and every pointer in a delegate are `nativeint`. Type aliases (KHR and EXT names) are abbreviations.
4. **Dispatch tables, not per-call lookups.** Three generated classes (`VkGlobalCommands`, `VkInstanceCommands`, `VkDeviceCommands`) load each command once through `vkGetInstanceProcAddr` or `vkGetDeviceProcAddr`. Each has its raw delegate and a wrapper: `const T*` as `inref<T>`, `T*` as `byref<T>`, arrays sized by a by-value count as spans (the count is their length, and spans that share a count must agree), pins held for the call only, `pAllocator` dropped (always NULL), and a VkResult outside the command's vk.xml success codes raised as `VulkanException`. A NULL entry raises `VulkanMissingCommandException`. Delegates, as in R3, because F# cannot emit `calli`.
5. **pNext chains cannot outlive their frame.** The recipe's feature and properties chains are byref-like structs (`[<IsByRefLike>]`), so the compiler keeps them on the stack of the frame that calls Vulkan. `VkChain.problems` checks a chain against vk.xml's `structextends` and `allowduplicate`; `Device.create` runs it before `vkCreateDevice`.
6. **The device check stays the shared gate,** now with every requirement of VulkanHeapRecipe section 1: Vulkan 1.4, `VK_EXT_descriptor_heap` with `descriptorHeap`, `shaderStorageBufferArrayDynamicIndexing`, `bufferDeviceAddress`, `timelineSemaphore`, `runtimeDescriptorArray`, `synchronization2`, `maintenance5`, `VK_KHR_shader_untyped_pointers` supported, the storage-buffer descriptor size equal to `bufferDescriptorSize`, the 64-slot heap within `maxResourceHeapSize`, `maxStorageBufferRange` of at least 1 GiB, and a compute-only queue family with timestamps. The heap limits must also be ones `Heap.vulkanGeometry` (Lrm.Gpu.Core, with which V1 sizes the heap) lays out: a positive `bufferDescriptorSize`, both descriptor alignments powers of two, and `bufferDescriptorSize` a multiple of `bufferDescriptorAlignment`. `DeviceCheck.heapReasons` states these rules, and the cpu tier checks that it and `DeviceCheck.geometry` agree with `Heap.vulkanGeometry` on KAT-2 and 14,400 more limit sets, so the check never accepts a device whose heap V1 then refuses.
7. **The push-data floor stays at 256 bytes,** although the recipe pushes a 128-byte ArgBlock and asserts only `maxPushDataSize` ≥ 128. 256 bytes is the D3D12 root-signature limit (64 DWORDs). With the same floor on both backends, an ArgBlock that grows up to that limit, for example for Phase 3's Roslyn arguments, needs no device to be re-qualified, and the two backends accept the same argument budget. The RTX 4080 reports exactly 256, so the floor rejects nothing here that the recipe would accept. `DeviceCheck.RecipePushDataSize` (128) records what the recipe needs.
8. **The oracle reads the runtime, not the generator.** The test exe dumps what the CLR actually lays out and calls: sizes, alignments measured as the offset after one byte, offsets, field sizes and kinds, enum values, handle sizes, constants, every delegate's signature, each struct's `StructureType`, and the `Extends` and alias metadata. cl.exe compiles it as C11 and C++17 static assertions against Vulkan-Headers 1.4.365. The sType values, structextends relations and aliases are checked against `vulkan.hpp` (`vk::T::structureType`, `vk::T::NativeType`, `vk::StructExtends`), which Khronos generates from the same registry with its own generator. Kind and size alone cannot tell apart mix-ups of the same width (a handle and a pointer to it, two 16-byte structs, two 32-bit enums, signed and unsigned), so the C++ half also states exact types: every field, return value and parameter is `std::is_same` as the C type its runtime type names (from the runtime's own `VkStruct`, `VkUnion`, `VkEnum` and `VkHandle` attributes and the scalar's width and sign; a FlagBits enum may stand for its Flags typedef), a `nativeint` is a pointer that is no handle, and every wrapper's `inref`, `byref` or span parameter points to exactly its element type, `const` exactly for `inref` and `ReadOnlySpan`. A handle is recognised structurally: `VK_DEFINE_HANDLE` and `VK_DEFINE_NON_DISPATCHABLE_HANDLE` both declare a pointer to a struct that no header defines, so `lrm::is_handle_v` is a pointer to an incomplete class (held to that by static assertions on handles, data pointers and function pointers). Wrapper parameters are matched to C parameters by name, and the oracle checks every raw delegate's parameter names, in order, against its `PFN_*` typedef in `vulkan_core.h`. The cpu tier also compiles mutants that must fail, and cross-checks R1's hand-written C declarations (`spikes/vk-heap/src/Layout.fs`, read with `dotnet fsi`, never built).
9. **The recipe's device is the default, diagnostics are opt-in.** `DeviceOptions.recipe` enables exactly what VulkanHeapRecipe section 1 says (one extension, the five features). `DeviceOptions.diagnostics` adds `VK_EXT_device_fault` with `deviceFault` and `VK_EXT_memory_budget` where supported, which V1's fault diagnostics need; `Extensions` adds further feature-less extensions such as `VK_KHR_calibrated_timestamps`. Device-level commands of instance extensions (debug utils) fall back to `vkGetInstanceProcAddr` when `vkGetDeviceProcAddr` returns NULL.
10. **A healthy device's fault query is an outcome.** On the RTX 4080 with driver 616.92, `vkGetDeviceFaultInfoEXT` returns `VK_ERROR_UNKNOWN` from the count query on a device that is not lost. `DeviceFault.query` therefore returns `NoFault result`, `Fault report` or `NotEnabled`, through the raw delegate.
11. **Names.** The namespace is `Lrm.Gpu.Vulkan.Interop`; V1 owns `Lrm.Gpu.Vulkan`. The CLI command is `lrm devices-vulkan [--json]`, the name S0a gave the stub and the twin of `lrm devices-d3d12`. The Python layout script that S0a moved to `tools/vkgen/legacy` is retired (deleted; git history keeps it), with its `.fantomasignore` entry.
12. **Callbacks are rooted by a GCHandle, and the instance destroys what its owners forgot.** `DebugMessenger` allocates a GCHandle for its callback delegate before `vkCreateDebugUtilsMessengerEXT` and frees it after `vkDestroyDebugUtilsMessengerEXT`, so the delegate lives as long as the driver can call it, whether or not anything references the messenger. The instance adopts each messenger and, when disposed, destroys the ones still alive (newest first) before `vkDestroyInstance`. No finalizer: destroying a Vulkan object from the finalizer thread could race the instance's own destruction, and a leaked root is safe where a collected delegate is not.

## Evidence

All on the development machine: NVIDIA GeForce RTX 4080, driver 616.92, device API 1.4.351, loader 1.4.341; VS 2022 Build Tools; vk.xml 1.4.365 (SHA-256 `4ab95383…428ca`); Vulkan-Headers 1.4.365 (archive SHA-256 `767d80b0…0ac6f`).

- **Generation.** `pwsh tools/vkgen/check.ps1`: 109 structs and unions, 10 inline arrays, 53 enums, 16 handles, 96 commands (5 global, 20 instance, 71 device), 7 extensions; the committed files are current. Two runs into a fresh tree give byte-identical files equal to the committed ones (cpu tier).
- **Oracle.** `pwsh tools/abi-oracle/vulkan/run.ps1`: 5,776 compile-time checks (2,801 C, 2,975 C++: 16 handles, 944 exact field types, 394 exact signature types, 82 wrapper pointer parameters of the 96 wrappers) against Vulkan-Headers 1.4.365, 0 failures; the parameter names of all 97 delegates match `vulkan_core.h`. All 27 mutants are reported: the 15 of kind and value (size, alignment, offset, field size, enum, 32-bit flag, constant, 64-bit flag, sType, structextends, field kind, array extent, parameter size, arity, string) and 12 of exact type (a handle parameter as a pointer, a pointer to a handle as the handle, two handles swapped, a signed return, a wrapper's wrong inref pointee, a span over another 16-byte struct, an output declared const, a signed field, two 32-bit enums swapped, two 16-byte structs swapped, two handles swapped in a field, a handle field as a pointer), while the kind lines that such a bug also changes pass unreported, as before. The spike cross-check: 48 structs and unions, 249 members of R1's declarations, 0 mismatches.
- **Device.** `VkDeviceCheck`: the RTX 4080 is ACCEPTED; `maxPushDataSize` 256, `bufferDescriptorSize` 16 (equal to `vkGetPhysicalDeviceDescriptorSizeEXT(STORAGE_BUFFER)`), heap geometry 1,024 / 1,024 / 96,768 / 97,792 bytes (the recipe's KAT-2), queue family 2, 64 timestamp bits at 1 ns, `shaderDenormPreserveFloat32` false.
- **gpu tier** (vulkan mutex): the recipe's device is created and destroyed twice with every enabled device command loaded; hello-compute (`args_echo`, the recipe's KAT-4) gives the 32 ArgBlock words and SHA-256 `74f5e898…3531` in two runs, bit-identical, with no poison word left, and the negative control (no dispatch) leaves all 32 poison words. Debug utils, the memory budget, the fault query, 15 cooperative-matrix shapes and calibrated timestamps work. A messenger dropped without Dispose still receives a `vkSubmitDebugUtilsMessageEXT` message after three full collections, and disposing its instance destroys it.
- **Calls.** Recording 3,000 wrapper calls (push data and barriers) into a real command buffer allocates 0 managed bytes (gpu tier); so do 3,000 calls on fake entry points, spans included (cpu tier). One call into the driver costs 60 to 80 ns for `vkCmdPushDataEXT` and 150 to 170 ns for `vkCmdPipelineBarrier2` across runs, driver work included (bench tier). A consumer compiled with `--tailcalls+` has no `tail.` at any inref or byref wrapper call; its raw-delegate control has one.
- **Unverified:** the described-fault path of `DeviceFault.query` (it needs a lost device, and a TDR on the shared GPU is out of bounds), and every device other than the RTX 4080.

## Consequences

- **V1** builds on `Device.create` (or the same chains), the generated wrappers and `DeviceCheck`, and keeps its own runtime state. It adds bindings by editing `bindings.json`, regenerating and refreshing the oracle in one commit (or asks R2).
- **R1** may want to correct VulkanHeapRecipe section 1: vk.xml 1.4.365 does not list `VK_KHR_shader_untyped_pointers` among `VK_EXT_descriptor_heap`'s dependencies (`depends="((VK_KHR_extended_flags,VK_KHR_maintenance5)+(VK_KHR_buffer_device_address,VK_VERSION_1_2),VK_VERSION_1_4)"`). The device check follows the contract text until it changes. Enabling `VK_EXT_device_fault` for diagnostics departs from the recipe's "one extension"; V1 and R1 decide whether the recipe allows it.
- **The spike** (`spikes/vk-heap`) opens the old namespace `Lrm.Gpu.Vulkan` and no longer compiles against this interop. It is not built anywhere; its `Layout.fs` is still read by the cross-check.
- **Reopens this ADR:** a new vk.xml pin (regenerate, re-run the oracle), a second device class with a different push-data limit, or a need for direct heap indexing.

## Alternatives

- **Hand-written structs checked at run time** (the old interop and the spike): fine for a dozen structs, unreviewable for 109, and both sides are transcriptions.
- **All enum values from all extensions:** the headers do this; here it would bind hundreds of values of extensions LRM never enables and make the generated file several times larger, with no ABI benefit because F# enums are open.
- **`delegate* unmanaged` calls through emitted `calli` stubs:** F# cannot write them, and dynamic IL is harder to review than delegates whose cost the bench tier measures.
- **Typed pointers (`nativeptr<T>`) in struct members:** safer to read, but they pull every pointee into the closure and add nothing the oracle does not already check.
